# 第一版范围

目标：在任意应用上点一下悬浮按钮，就能看到当前屏幕（或框选区域）的译文，译文盖在原文位置上。

## 第一版要做的

按使用顺序：

1. **悬浮按钮**
   - 无障碍服务开启后，在屏幕边上显示一个小按钮（`TYPE_ACCESSIBILITY_OVERLAY`，不需要悬浮窗权限）。
   - 可拖动，松手贴边；位置记住。
   - 点一下 = 翻译当前屏幕；长按 = 进入框选。
2. **先读界面文字**（不截屏）
   - 遍历 `getWindows()` / `rootInActiveWindow` 的节点，取有文字的可见节点：`text`、`contentDescription`、位置 `getBoundsInScreen()`。
   - 去掉我们自己的悬浮层、系统栏、空白和重复节点；按位置排序、合并成段。
   - 判断"读到了没有"：可见区域里有足够多的文字节点就用这条路，否则走截屏 OCR。
   - 好处：快、准、不耗电，坐标精确。
3. **读不到就截屏**
   - 用 `AccessibilityService.takeScreenshot()`（安卓 11+），得到硬件位图，转成软件位图再处理。
   - 系统限制两次截屏之间有最短间隔（约 1 秒，随系统版本不同），连点时要排队或提示。
   - 截屏前先把自己的悬浮按钮和旧译文藏起来，避免截进去。
4. **框选**
   - 长按悬浮按钮后出现全屏透明层，手指拖出矩形，只翻译框内的内容（读节点时按矩形过滤；截屏时裁剪）。
5. **本地 OCR**
   - ONNX Runtime Android，进程内运行。
   - 检测：PP-OCRv6 tiny（共用）；识别：泰语用 `th_PP-OCRv5_mobile_rec`，中英文用 PP-OCRv6 识别模型。
   - 语言在设置页手动选（第一版不做自动判断）。
   - 预处理、后处理参数照 Windows 版（见 `docs/移植清单.md`）。
6. **调翻译 API**
   - 第一版先接 1～2 个：一个免密钥的网页接口（如 Google `translate_a/single`）+ 一个需要密钥的（DeepL 或 OpenAI 兼容接口，二选一，和用户确认）。
   - 密钥在设置页填写，只存在手机上。
   - 一次请求发多段，减少请求次数。
7. **在原位置显示译文**
   - 用无障碍悬浮层，按每段原文的屏幕坐标画一个底色块 + 译文，字号按原文框高度估算。
   - 点译文或点空白处关闭；悬浮层不拦截下层应用的触摸（关闭前除外）。
8. **启动/设置页**
   - 显示无障碍服务是否已开启，一键跳到系统设置。
   - 首次开启引导（见下文）。
   - 选源语言、目标语言、翻译服务、填密钥。

## 第二步（第一版之后）

- **输入框替换翻译**：选中输入框 → 翻译 → 用 `ACTION_SET_TEXT` 把译文写回去。
- 自动判断源语言。
- 更多翻译服务、更多 OCR 语言（日文、韩文）。
- 译文复制、朗读。

## 第一版不做的

- 实时/连续翻译（字幕、游戏对话自动刷新）。
- 大模型、本地推理服务、在线 OCR。
- `MediaProjection` 录屏截图方式（需要每次同意，且常驻通知）。
- "显示在其他应用上层"悬浮窗权限。
- 竖排文字、倾斜文字、注音（ruby）等 Windows 版的复杂排版处理。
- Google Play 上架、多语言界面、平板适配。

## 需要的权限

| 权限 / 能力 | 用途 | 怎么获得 |
| --- | --- | --- |
| 无障碍服务 | 读界面文字、截屏、显示悬浮层、写输入框 | 用户在系统设置里手动开启 |
| `canTakeScreenshot`（无障碍配置里声明） | 无障碍截屏 | 随无障碍服务一起生效 |
| `INTERNET` | 调翻译 API | 安装即有 |
| 忽略电池优化（可选） | 防止后台被杀导致服务掉线 | 引导用户手动设置 |

不需要：悬浮窗权限、存储权限、录屏权限。

## 首次开启引导（设置页上按顺序显示）

1. **安卓 13+：先"允许受限设置"**
   侧载的 APK（不是从应用商店装的）默认不能开无障碍，开关是灰的。步骤：
   系统设置 → 应用 → 贴译 → 右上角 ⋮ → "允许受限设置"（需要先去无障碍里点一次贴译，提示被拦截后这个菜单才会出现）。
   各品牌菜单位置不同，等知道测试手机型号后补具体路径。
2. **开启无障碍服务**：系统设置 → 无障碍 → 已下载的应用 / 已安装的服务 → 贴译 → 开启。
3. **国产系统（小米/红米 HyperOS、华为/荣耀、OPPO/一加 ColorOS、vivo OriginOS 等）**：
   - 电池：设为"无限制"/加入白名单，否则息屏后服务会被杀，无障碍开关自己关掉。
   - 允许自启动。
   - 最近任务里给贴译"加锁"。
4. 引导页检测每一项的状态（能检测的打勾），检测不了的给出跳转按钮和文字说明。

## 风险点

- **受限设置 / 无障碍被关**：侧载应用在安卓 13+ 必须手动解锁；国产系统杀后台后会顺带关掉无障碍，需要用户每次重开。要在主页醒目提示状态。
- **截屏失败**：
  - 有 `FLAG_SECURE` 的界面（银行、部分视频、密码页）截出来是黑的或直接报错。
  - 两次截屏间隔太短会报错（`ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT`）。
  - 部分厂商系统可能改了行为，需真机验证。
- **节点文字不可靠**：有些应用的节点文字和显示的不一致、位置不准、或整页是一个 WebView/Canvas。需要判断"读到的文字是否可信"，不行就回退到 OCR。
- **OCR 速度和内存**：手机 CPU 跑检测 + 识别，大截图可能要 1～几秒。检测前要缩图（长边上限），识别按行批量。模型常驻内存约几十 MB，空闲时要释放。
- **APK 体积**：ONNX Runtime 每个 CPU 架构的原生库约 10～20 MB，加上模型。只打 `arm64-v8a` 可以控制体积。
- **泰文渲染**：泰文有上下标元音和声调符号，原文框高度估字号时要留余量；译文是中文时问题不大。
- **翻译接口**：免密钥的网页接口随时可能改版或限流，需要备用接口。
- **Google Play Protect**：侧载带无障碍的应用可能被提示"有害"，装的时候要点"仍然安装"。
- **悬浮层遮挡和触摸**：悬浮层处理不好会挡住下层应用的点击，或者在输入法、系统弹窗上面/下面显示异常。
