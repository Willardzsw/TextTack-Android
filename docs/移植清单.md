# 移植清单（Windows 版 → Kotlin）

参考来源：Windows 版仓库 `E:\Claude\overtranslate`（只读，不修改；不读、不复制任何 API 密钥；不碰 `profile-thai` 文件夹）。

Windows 版的 OCR 用的是 NuGet 包 **RapidOcrNet 3.0.0**（BobLd/RapidOcrNet，Apache-2.0，源自 RapidAI/RapidOCR），自己的代码 `OnnxOcrEngine.cs` 在它外面包了一层：改了缩图、对齐、阈值，并通过反射调用库里的方法。安卓版没有这个库，**库里的检测/识别前后处理也要一起用 Kotlin 重写**。可以对照的库源码副本在 `E:\Claude\overtranslate\.test-artifacts\ocr-performance\`（`TextDetector.cs`、`TextRecognizer.cs`、`RapidOcr.cs`）。

## 一、OCR：要移植的逻辑

### 1. 检测（PP-OCRv6 tiny，DB 算法）

来源：`src/OverTranslate/Services/Ocr/OnnxOcrEngine.cs`（`CreateOptions`、`CreateDetectorFrame`、`AlignForDetector`、`ShippedDetector`）+ RapidOcrNet `TextDetector.cs`。

| 项目 | Windows 版取值 | 说明 |
| --- | --- | --- |
| 缩图上限 | 长边 2048（`ScreenshotDetectSize`） | 只缩小不放大；手机截图长边常是 2400+，会缩。手机上可能要再小（1280～1600）换速度，真机测 |
| 缩图算法 | Mitchell 三次插值 | 安卓用 `Bitmap.createScaledBitmap(filter=true)` 是双线性，效果需对比 |
| 两轴比例 | `RatioX`、`RatioY` 分开记 | 映射回原图时每个轴单独除，避免偏一两个像素 |
| 对齐 | 宽高 + 2×padding 补到 32 的倍数（`DetectorAlignment = 32`），右/下补透明（黑） | 不拉伸，只补边 |
| 边距 padding | 8 像素（`DetectorPadding = 8`） | 库默认 50，Windows 版实测 8 最好（框选时开头的字不丢） |
| 归一化 | mean = 127.5、std = 127.5（三通道相同） | tiny 检测器专用，**不是** ImageNet 那组；用 ImageNet 会漏字（Windows 版 issue #69） |
| 通道顺序 | BGR，NCHW float32 | 安卓 Bitmap 是 ARGB，要换成 BGR |
| 二值化阈值 BoxThresh | 0.2 | 概率图 > 0.2 算文字 |
| 框得分阈值 BoxScoreThresh | 0.4 | 框内平均概率低于它丢弃 |
| 外扩比例 UnClipRatio | 1.4 | |
| 膨胀 | 半径 1 的膨胀（`SKImageFilter.CreateDilate(1,1)`） | 对二值图 |
| 方向分类 cls | 关闭（`DoAngle = false`） | 第一版不需要 cls.onnx |

后处理步骤（照 RapidOcrNet `TextDetector.GetTextBoxes`）：
1. 输出概率图 → 阈值二值化 → 膨胀。
2. 找轮廓（库里用 `PContour.FindContours`）。
3. 每个轮廓求最小外接矩形 `GetMiniBox`，短边太小丢弃。
4. 算框内平均概率 `GetScore`，低于 0.4 丢弃。
5. `Unclip`：按 面积×1.4/周长 向外扩（库用 Clipper2 做多边形偏移）。
6. 再求一次最小外接矩形，映射回原图坐标，按阅读顺序排序 `SortBoxesInReadingOrder`。

**依赖选择（回家后和用户定）**：
- 方案 A：纯 Kotlin 实现轮廓、最小外接矩形、矩形外扩（矩形外扩不需要 Clipper，可以直接按距离放大矩形）。体积最小，推荐。
- 方案 B：引入 OpenCV Android（Apache-2.0），`findContours`/`minAreaRect` 现成，但每个架构多 10 MB 以上。

### 2. 识别（CRNN + CTC）

来源：RapidOcrNet `TextRecognizer.cs`。

| 项目 | 取值 |
| --- | --- |
| 输入高度 | 48，宽度按比例缩放 |
| 宽度 | 每批按最宽的补零到 `48 × max(w/h, 320/48)` |
| 归一化 | mean = 127.5、std = 127.5（即 `(x/255 - 0.5)/0.5`） |
| 裁剪 | 按检测框（四边形）透视变换裁出横条；高明显大于宽的竖条要旋转 |
| 字典 | 第 0 位插入空白符 `#`（CTC blank），然后逐行读 `dict.txt`（只去掉行尾 CR/LF，**不要 trim**），最后追加一个空格 `" "` |
| 解码 | 每一步取 argmax；跳过 0（blank）；和上一步相同的跳过；记录每个字的分数 |
| 最低置信度 | 0.6（`MinRecognitionConfidence`），低于它的行丢弃 |

泰文字典要点（来自 `thai/provenance.json`）：524 个条目 + blank + 空格 = 526 类输出，**字符顺序不能改**。

### 3. 识别后的整理（第一版只做最简单的）

来源：`OnnxOcrEngine.cs` 里的 `ApplyBlockFilters`、`NormalizeBlock`、`EstimateGlyphHeight`，以及 `OcrTextBlockGrouper.cs`（1840 行）。

- 第一版：只把检测框按行合并成段落（同一列、行距相近、左对齐的合并），字号按框高 × 0.82 估算。
- 先不移植：竖排（`Vertical*.cs`）、倾斜（`Tilted*.cs`）、注音（`*Ruby*.cs`）、彩色框修复（`ChromaticBoxRepair.cs`）、DirectML 加速。
- 泰文专用：`MapPointsToSource` 里对泰文把框夹在图像范围内（`ClampToImage`），要保留。

### 4. 线程和内存

来源：`OcrThreadBudget.cs`、`OnnxOcrEngine.cs` 的 `IdleReleaseDelay`。

- 空闲 1 分钟后释放模型会话；安卓上同样做，避免常驻内存。
- 线程数：手机先用 `intraOpNumThreads = 大核数`（2～4），真机测。

## 二、翻译服务：要移植的

来源：`src/OverTranslate.Translation/`（各引擎）、`src/OverTranslate/Services/TranslationService.cs`、`Services/Providers/`。

| 服务 | Windows 版文件 | 接口 | 需要密钥 | 第一版 |
| --- | --- | --- | --- | --- |
| Google（网页接口） | `Google/GoogleWebTranslator.cs` | `translate.googleapis.com/translate_a/single` | 否 | 是（候选） |
| DeepL | `DeepL/DeepLTranslator.cs` | `api-free.deepl.com/v2/translate`、`api.deepl.com/v2/translate` | 是 | 二选一 |
| OpenAI 兼容 | `OpenAi/*.cs`、`Providers/OpenAiCompatibleProvider.cs` | `{BaseUrl}/chat/completions` | 视服务而定 | 二选一 |
| Bing / 微软 / 有道 / 腾讯交互翻译 / Yandex | 对应文件夹 | 网页接口，需要会话/签名 | 否 | 以后 |

要移植的通用逻辑：
- `BatchTranslator.cs`、`TranslationRequestChunks.cs`：多段合并成一次请求、按长度切块。
- `LanguageCodes.cs`、`Providers/EngineLanguage.cs`：各服务的语言代码对照（泰语 `th`、简中 `zh-CN`/`zh-Hans` 等）。
- `Providers/ResilientProvider.cs`：主接口失败时换备用接口（第二步再做）。
- `OpenAi/OpenAiPrompt.cs`：翻译提示词模板（如果选 OpenAI 兼容）。

安卓上 HTTP 用 OkHttp 或 `HttpURLConnection`，JSON 用 `org.json` 或 kotlinx.serialization（定方案时再选）。
